- (decision) AD-1: Base platform is QloApps (fork of PrestaShop). PHP >8.0 <8.5, MySQL/MariaDB. All custom work delivered as QloApps modules (addons), never patch core files.
- (decision) AD-2: Flat multi-branch via QloApps built-in hotel system. Each hotel = 1 branch. Data filtered by hotel_id. No multi-tenant DB isolation.
- (decision) AD-3: Payment addon (qlovietqr) is the only custom module. Uses VietQR/PayOS HTTP API to generate QR image URL. Single webhook endpoint for reconciliation.
- (decision) AD-4: Deployment via Docker Compose (nginx + php-fpm + mysql). Single server. No k8s, no CI/CD pipeline for 50-room hotel.
- (decision) AD-5: Google Maps embed via iframe (My Maps), not Maps JS API. Zero API cost.
- (assumption) [ASSUMPTION] VietQR API (vietqr.io) or PayOS supports webhook callback with signature verification.
- (assumption) [ASSUMPTION] QloApps Employee permission system supports hotel-level access restriction out of the box.
